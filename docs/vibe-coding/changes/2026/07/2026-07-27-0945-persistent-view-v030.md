# 持久化网页视图升级到 v0.3.0

任务：升级 LZClaw 使用的 `@fudanda/electron-persistent-view`，并同步长期合并契约。
作者：fudanda <314553951@qq.com>
时间：2026-07-27 09:45 Asia/Shanghai
AI 协助：Codex 参与包实现、发布、LZClaw 依赖升级、测试和文档同步。
Review：未创建独立 Review、PR 或 LZClaw 提交。

## 为什么改

`0.2.0` 已解决视图隐藏保活和销毁清理问题，但异步 `open()` 仍缺少明确的
竞争结果、主动取消和超时契约，宿主也无法订阅生命周期状态或主动刷新
Chromium Session 存储。安全偏好还需要覆盖 Worker、子框架、混合内容、
WebView、实验特性和 Blink 特性。

## 改了什么

- LZClaw 将依赖精确升级为
  `@fudanda/electron-persistent-view@0.3.0`，不使用范围版本或本地 `file:`
  依赖。
- `open()` 新增 `opened`、`superseded` 和 `closed` 结果，并支持
  `AbortSignal` 与正数超时；现有忽略返回值的 LZClaw 调用保持兼容。
- 包新增 `flushStorageData()` 和状态订阅，不改变 LZClaw 当前登录、退出、
  业务中心或网关生命周期。
- 包强制更完整的安全 WebPreferences，并在运行时丢弃通过类型断言注入的
  危险配置。
- 长期定制台账和持久化视图架构文档同步到 `0.3.0` 契约。

## 合并时如何处理

- `package.json` 和 `package-lock.json` 冲突时保留精确版本 `0.3.0`，同时
  接收上游其他依赖更新。
- 登录和业务中心控制器仍共享 `persist:lzclaw-web`，不要改回
  `defaultSession`、iframe 或临时 Session。
- 新版本返回值是兼容性新增。未来需要处理导航取消或超时时，应显式检查
  `open()` 结果，不要用延时或重复加载绕过生命周期。
- 继续执行 `docs/lzclaw-fork-customizations.md` 中的登录、退出、覆盖层和
  业务中心运行验收。
